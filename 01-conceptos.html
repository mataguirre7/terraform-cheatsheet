Terraform · Cheatsheet 01

Conceptos clave de Terraform

Terraform es infraestructura como código: describís en archivos .tf los servidores, redes, bases de datos o contenedores que querés, y Terraform los crea, modifica o borra para que la realidad coincida con el código.

1

El flujo de trabajo

Cuatro comandos que vas a repetir siempre.

✓

Antes del plan: terraform fmt (formatea) y terraform validate (revisa sintaxis y referencias).

i

Declarativo: no escribís “creá un servidor”, escribís “tiene que existir este servidor”. Si ya existe igual, no hace nada.

!

apply y destroy tocan infraestructura real (y pueden costar plata). Leé siempre el plan antes de confirmar.

2

Cómo funciona por dentro

Terraform no sabe nada de AWS ni de Docker: delega en providers, plugins que hablan con cada API.

i

Hay miles de providers en el Terraform Registry (registry.terraform.io): nubes, GitHub, Cloudflare, Kubernetes, bases de datos… Todos se usan con la misma sintaxis.

3

Estado deseado, estado guardado y estado real

El plan es la diferencia entre lo que pide el código y lo que existe.

i

refresh: antes de planear, Terraform lee la infra real y actualiza lo que sabe de cada recurso.

!

Drift: alguien cambió algo a mano en la consola. El próximo plan lo detecta y propone volverlo a lo que dice el código.

✕

Si perdés el .tfstate, Terraform cree que no existe nada e intenta crear todo de nuevo. Por eso en equipo va en un backend remoto.

4

Cómo leer un plan

El símbolo de la izquierda dice qué va a pasar con cada recurso.

Símbolos

SímboloSignificaCuándo
+CrearRecurso nuevo en el código
~Modificar en el lugarCambió un atributo editable
-DestruirLo sacaste del código
-/+Reemplazar (borra y crea)Cambió un atributo que no se puede editar
+/-Reemplazar (crea y después borra)Con create_before_destroy
<=LeerUn data que se resuelve al aplicar
!

Ojo con -/+ y # forces replacement: en una base de datos significa perder los datos.

Ejemplo de salida

Terraform will perform the following actions:

  # docker_container.chanchito will be created
  + resource "docker_container" "chanchito" {
      + name    = "chanchito"
      + image   = "sha256:4f2a…"
      + id      = (known after apply)
    }

  # docker_container.monguito must be replaced
-/+ resource "docker_container" "monguito" {
      ~ image   = "mongo:6" -> "mongo:7" # forces replacement
    }

Plan: 2 to add, 0 to change, 1 to destroy.
i

(known after apply): el valor lo decide la plataforma al crear el recurso (IDs, IPs).

5

Glosario

Las piezas que vas a ver en cualquier proyecto.

Bloque

provider

Plugin que traduce tus recursos a llamadas a una API (AWS, Azure, Docker…). Se configura con región, credenciales, host.

Bloque

resource

Algo que Terraform crea y administra: una VM, un bucket, un contenedor. Es el bloque central.

  • resource "tipo" "nombre" { … }
Bloque

data

Lee algo que ya existe y no administra Terraform (la última imagen de Ubuntu, una VPC creada por otro equipo).

Bloque

variable

Parámetro de entrada (región, tamaño, nombre del entorno). Se usa como var.nombre.

Bloque

output

Valor que Terraform muestra al terminar o que exporta un módulo (una IP, una URL).

Bloque

locals

Valores calculados internos para no repetir expresiones. Se usan como local.nombre.

Organización

module

Carpeta de .tf reutilizable con entradas (variables) y salidas (outputs). Toda carpeta es un módulo: la que ejecutás es el root module.

Estado

state

Archivo JSON (terraform.tfstate) que relaciona cada recurso del código con su ID real. Puede tener secretos.

Estado

backend

Dónde se guarda el estado: local (default), S3, Azure Storage, GCS o HCP Terraform. Los remotos permiten bloqueo y trabajo en equipo.

Estado

workspace

Varios estados para la misma configuración (dev, prod). Útil para pruebas; para entornos reales suelen preferirse carpetas separadas.

Archivo

.terraform.lock.hcl

Fija las versiones exactas de los providers (como package-lock.json). Se sube a git.

Carpeta

.terraform/

Providers y módulos descargados por init (como node_modules). No se sube a git.

Terraform vs OpenTofu

En 2023 Terraform pasó a licencia BUSL. La comunidad creó OpenTofu, un fork libre (Linux Foundation) compatible con la misma sintaxis.

  • Los comandos son iguales: tofu init, tofu plan, tofu apply…
  • Todo lo de estas hojas funciona en los dos, salvo funciones muy nuevas de cada uno.
  • Instalar en Windows: winget install Hashicorp.Terraform o winget install OpenTofu.Tofu.
i

Alternativas con otro enfoque: Pulumi (infra con TypeScript/Python), CloudFormation (solo AWS), Bicep (solo Azure).
