Terraform · Cheatsheet 00

Empezar con Terraform desde cero

Una guía para hacer en orden, en Windows, sin cuenta de AWS ni de Azure. En vez de crear servidores en la nube, Terraform va a crear un contenedor en tu Docker Desktop: el flujo de trabajo es exactamente el mismo, pero es gratis y se borra en un segundo. Cada paso explica qué hace y muestra lo que deberías ver.

Términos de esta página

Con más detalle en Conceptos.

Infraestructura
Todo lo que una app necesita para correr: servidores, redes, bases de datos, contenedores, DNS…
Infraestructura como código
Describir esa infraestructura en archivos de texto, en vez de crearla a mano con clics. Los archivos se guardan en Git y se pueden repetir.
Terraform
El programa que lee esos archivos y crea, cambia o borra lo que describen.
Archivo .tf
Un archivo de configuración de Terraform, escrito en un lenguaje llamado HCL.
Provider
Un plugin que le enseña a Terraform a hablar con un servicio (AWS, Azure, Docker…). Se descarga solo.
Recurso (resource)
Una cosa concreta que Terraform administra: una imagen, un contenedor, una máquina virtual…
Estado (state)
El archivo terraform.tfstate, donde Terraform anota lo que creó, para saber qué cambiar la próxima vez.
Plan
La lista de cambios que Terraform haría, mostrada antes de hacerlos.
0

Requisitos

Docker Desktop instalado y abierto: es donde Terraform va a crear el contenedor (en la colección de Docker, la hoja “Empezar desde cero” explica cómo instalarlo). Comprobalo con docker version: tienen que aparecer las secciones Client y Server.

Un editor de texto. Con VS Code, instalá la extensión HashiCorp Terraform: colorea los archivos .tf y avisa de errores mientras escribís.

1

Instalar Terraform

Una sola vez.

winget install Hashicorp.Terraform
winget es el instalador de programas que trae Windows. Este comando descarga Terraform y lo agrega al PATH (la lista de carpetas donde Windows busca comandos). Al terminar, cerrá y volvé a abrir la terminal para que la vea.
terraform -version
Muestra la versión instalada. Si aparece, la instalación funcionó.
Terraform v1.1x.x
on windows_amd64
✕

“terraform no se reconoce como nombre de un cmdlet”: la terminal se abrió antes de instalar. Cerrala del todo (también VS Code, si usás su terminal) y abrila de nuevo.

i

OpenTofu es una copia libre de Terraform que funciona igual: winget install OpenTofu.Tofu y en todos los comandos se escribe tofu en vez de terraform.

2

Tu primer archivo .tf

Un servidor web nginx, como contenedor de Docker.

  1. Creá una carpeta vacía, por ejemplo C:\proyectos\hola-terraform, y abrila en VS Code.
  2. Creá adentro un archivo llamado main.tf con el contenido de la derecha.
  3. Abrí una terminal en esa carpeta (en VS Code: Terminal → New Terminal). Terraform lee todos los .tf de la carpeta donde lo ejecutás.

El archivo tiene cuatro bloques:

  1. terraform: qué providers necesita este proyecto y de dónde bajarlos. ~> 3.0 = cualquier versión 3.x.
  2. provider "docker": cómo conectarse a Docker. En Windows se habla con Docker Desktop por un named pipe (un canal interno de Windows); esa es la dirección rara de host.
  3. resource "docker_image" "nginx": “quiero que exista la imagen nginx”. El primer texto es el tipo de recurso; el segundo, el nombre que vos le das para referirte a él.
  4. resource "docker_container" "web": “quiero un contenedor con esa imagen, con el puerto 80 publicado en el 8080 de mi PC”. docker_image.nginx.image_id es una referencia: usa el ID de la imagen del bloque anterior, y eso le dice a Terraform que tiene que crear la imagen primero.
main.tf
terraform {
  required_providers {
    docker = {
      source  = "kreuzwerker/docker"
      version = "~> 3.0"
    }
  }
}

provider "docker" {
  # Windows + Docker Desktop
  host = "npipe:////.//pipe//docker_engine"
  # En Linux o macOS sería:
  # host = "unix:///var/run/docker.sock"
}

# La imagen: equivale a "docker pull nginx:1.27"
resource "docker_image" "nginx" {
  name = "nginx:1.27"
}

# El contenedor: equivale a
# "docker run -d --name hola-web -p 8080:80 nginx:1.27"
resource "docker_container" "web" {
  name  = "hola-web"
  image = docker_image.nginx.image_id

  ports {
    internal = 80     # puerto dentro del contenedor
    external = 8080   # puerto en tu PC
  }
}
3

terraform init: preparar la carpeta

Se corre una vez por proyecto (y de nuevo si agregás providers o módulos).

terraform init
Lee el bloque terraform, descarga el provider de Docker y lo guarda en una carpeta oculta .terraform/. También crea .terraform.lock.hcl, que anota la versión exacta descargada para que todos los que usen el proyecto tengan la misma. No crea nada en Docker todavía.

Si usás Git: .terraform/ y *.tfstate van al .gitignore; .terraform.lock.hcl sí se sube.

4

terraform plan: ver qué haría

No cambia nada. Es el paso para revisar antes de tocar.

terraform plan
Compara lo que dicen tus archivos con lo que anotó en el estado (ahora vacío, porque nunca creó nada) y muestra la diferencia. Cada recurso lleva un símbolo al principio:
+
Se va a crear.
~
Se va a modificar sin borrarlo.
-
Se va a borrar.
-/+
Se va a reemplazar: borrar y crear de nuevo (pasa cuando un cambio no se puede hacer en el lugar).

(known after apply) = un valor que recién se conoce al crear el recurso, como el ID que le asigne Docker.

Terraform will perform the following actions:

  # docker_container.web will be created
  + resource "docker_container" "web" {
      + id    = (known after apply)
      + image = (known after apply)
      + name  = "hola-web"
      ...
      + ports {
          + external = 8080
          + internal = 80
          ...
        }
    }

  # docker_image.nginx will be created
  + resource "docker_image" "nginx" {
      + id       = (known after apply)
      + image_id = (known after apply)
      + name     = "nginx:1.27"
    }

Plan: 2 to add, 0 to change, 0 to destroy.

La última línea es el resumen: 2 para crear, nada para cambiar ni borrar.

5

terraform apply: crearlo de verdad

terraform apply
Vuelve a calcular el plan, te lo muestra y pregunta antes de hacer nada. Escribí yes (exactamente esa palabra) y Enter. Cualquier otra respuesta cancela.

  Only 'yes' will be accepted to approve.

  Enter a value: yes

docker_container.web: Creating...

Comprobar

  1. Abrí http://localhost:8080: aparece “Welcome to nginx!”.
  2. En Docker Desktop, en Containers, aparece hola-web corriendo. También con docker ps.
  3. En la carpeta apareció terraform.tfstate: ahí Terraform anotó lo que creó (paso 7).
terraform apply
Probá correrlo otra vez sin cambiar nada: dice “No changes. Your infrastructure matches the configuration.” Terraform no repite lo que ya existe; solo corrige diferencias. Por eso se puede ejecutar todas las veces que haga falta.
6

Cambiar algo y volver a aplicar

El ciclo de todos los días: editar el archivo → plan → apply.

En main.tf, cambiá external = 8080 por external = 8081 y guardá.

terraform plan
  # docker_container.web must be replaced
-/+ resource "docker_container" "web" {
      ~ ports { # forces replacement
          ~ external = 8080 -> 8081 # forces replacement
            internal = 80
        }
    }

Plan: 1 to add, 0 to change, 1 to destroy.

El puerto de un contenedor no se puede cambiar con el contenedor andando, así que Terraform lo va a reemplazar (-/+): borra el viejo y crea uno nuevo. forces replacement marca qué cambio lo obliga. La imagen no aparece porque no cambió.

terraform apply
Confirmá con yes. Ahora la página está en http://localhost:8081 y ya no en 8080.
!

Leé siempre el plan antes de confirmar. En la nube, un -/+ sobre una base de datos significa borrarla y crear una vacía.

7

Mirar el estado

Lo que Terraform recuerda de lo que creó.

terraform state list
Lista los recursos que Terraform está administrando, con la forma tipo.nombre que usaste en el archivo.
docker_container.web
docker_image.nginx
terraform state show docker_container.web
Todos los datos guardados de un recurso: ID, nombre, puertos, IP dentro de Docker…
!

No borres ni edites terraform.tfstate a mano. Si se pierde, Terraform “olvida” lo que creó: los contenedores siguen existiendo, pero el próximo apply intentará crearlos de nuevo y fallará porque el nombre ya está en uso. En equipos, el estado se guarda en un lugar compartido (ver Variables y estado).

i

Si borrás el contenedor desde Docker Desktop, el próximo terraform plan lo detecta y propone crearlo otra vez: el archivo dice que tiene que existir.

8

terraform destroy: borrar todo y siguientes pasos

terraform destroy
Borra todo lo que figura en el estado de esta carpeta (y nada más). Muestra el plan con - en cada recurso y pide yes. Los archivos .tf quedan intactos: un terraform apply vuelve a crear todo igual.

Resumen del ciclo

init
Prepara la carpeta y descarga providers.
plan
Muestra qué cambiaría, sin tocar nada.
apply
Hace los cambios (pide confirmación).
destroy
Borra todo lo que creó.
