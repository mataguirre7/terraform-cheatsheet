Terraform · Cheatsheet 02

La CLI de Terraform

Todos los comandos se ejecutan en la carpeta de los .tf. Los valores en <rosa> se reemplazan. Con OpenTofu, cambiá terraform por tofu.

Instalar Ciclo básico plan y apply init Outputs y consola state e import Workspaces Variables de entorno CI y extras
1

Instalar y verificar

Es un único ejecutable.

Instalar

winget install Hashicorp.Terraform
Windows. Cerrá y abrí la terminal después.
winget install OpenTofu.Tofu
La alternativa libre (comando tofu).
brew install hashicorp/tap/terraform
macOS.

Verificar

terraform version
Versión de Terraform y de los providers del proyecto.
terraform -help
terraform plan -help
Ayuda general o de un comando.
terraform -install-autocomplete
Autocompletado (bash/zsh).
2

Ciclo básico

En este orden.

Preparar y revisar

terraform init
Descarga providers y módulos, configura el backend. Crea .terraform/ y .terraform.lock.hcl.
terraform fmt
Formatea los .tf con el estilo estándar. -recursive para subcarpetas.
terraform validate
Revisa sintaxis, tipos y referencias (sin tocar la infra).

Aplicar y borrar

terraform plan
Muestra qué cambiaría. No modifica nada.
terraform apply
Hace un plan, lo muestra y pide confirmación (yes).
terraform destroy
Borra todo lo que administra este estado. Pide confirmación.
terraform plan -destroy
Ver qué borraría destroy, sin borrar.
3

plan y apply a fondo

Guardar el plan garantiza que se aplica exactamente lo que revisaste.

Planes guardados

terraform plan -out=tfplan
terraform apply tfplan
El flujo recomendado en equipo y en CI.
terraform show tfplan
terraform show -json tfplan
Ver un plan guardado (legible o JSON).
terraform apply -auto-approve
Sin confirmación. ⚠ Solo en automatización o entornos descartables.

Pasar variables

terraform plan -var="entorno=dev"
Una variable suelta.
terraform plan -var-file="prod.tfvars"
Un archivo de valores.
Sin -var: lee terraform.tfvars y *.auto.tfvars solos, y pregunta lo que falte. Orden completo en Variables y estado.

Planes parciales y especiales

terraform apply -replace="docker_container.chanchito"
Fuerza recrear un recurso (reemplaza al viejo taint).
terraform plan -target="docker_container.chanchito"
Solo ese recurso y sus dependencias. ⚠ Para emergencias, no para el día a día.
terraform apply -refresh-only
Actualiza el estado con la realidad (acepta el drift) sin cambiar infraestructura.
terraform plan -detailed-exitcode
Código de salida 0 = sin cambios, 2 = hay cambios, 1 = error. Útil en CI para detectar drift.
4

init: providers, módulos y backend

Volvé a correrlo cada vez que cambies providers, módulos o el backend.

Variantes de init

terraform init -upgrade
Actualiza providers/módulos a la versión más nueva que permitan tus restricciones (reescribe el lock file).
terraform init -reconfigure
Cambió el backend y no querés migrar el estado.
terraform init -migrate-state
Cambió el backend y querés copiar el estado al nuevo (ej. de local a S3).
terraform init -backend-config="backend-dev.hcl"
Valores del backend desde un archivo (bucket, key…) para no hardcodearlos.

Providers y lock file

terraform providers
Qué providers usa el proyecto y de dónde vienen.
terraform providers lock -platform=windows_amd64 -platform=linux_amd64
Registra en el lock file los hashes de varias plataformas (tu PC Windows + CI Linux).
terraform get -update
Solo actualizar módulos.
5

Outputs, consola y grafo

Consultar lo que hay sin cambiar nada.

Outputs

terraform output
Todos los outputs del estado actual.
terraform output -raw url
Un valor sin comillas (para usar en scripts).
terraform output -json
Todo en JSON (incluye los marcados sensitive).
terraform show
El estado completo, legible.

Consola y grafo

terraform console
REPL para probar expresiones y funciones con tus variables reales.
> cidrsubnet("10.0.0.0/16", 8, 1)
"10.0.1.0/24"
> upper(var.entorno)
"DEV"
Ejemplo de sesión. Salís con exit.
terraform graph | dot -Tsvg > grafo.svg
Grafo de dependencias (requiere Graphviz).
6

state e import

Operaciones sobre el estado. Hacé un backup antes: terraform state pull > backup.tfstate.

Inspeccionar el estado

terraform state list
Todos los recursos que administra.
terraform state show docker_container.chanchito
Atributos de un recurso.
terraform state pull > backup.tfstate
Descarga el estado (también el remoto).

Modificar el estado

terraform state mv docker_container.app docker_container.chanchito
Renombrar sin destruir. Hoy es mejor un bloque moved en el código.
terraform state rm docker_container.chanchito
Terraform deja de administrarlo; el recurso real sigue existiendo. Hoy existe el bloque removed.
terraform force-unlock <lock-id>
Liberar un lock trabado. ⚠ Solo si nadie más está aplicando.

Importar lo que ya existe

import {
  to = docker_container.monguito
  id = "<id-del-contenedor>"
}
Bloque import en el código: se importa con el próximo apply y queda revisado en el plan.
terraform plan -generate-config-out=generado.tf
Junto con el bloque import, escribe el resource por vos.
terraform import docker_container.monguito <id>
Forma vieja por CLI (necesita el resource ya escrito).
7

Workspaces

Un estado separado por workspace, con el mismo código.

Comandos

terraform workspace list
El actual tiene *. Siempre existe default.
terraform workspace new dev
terraform workspace select dev
Crear / cambiar. select -or-create dev hace las dos.
terraform workspace show
terraform workspace delete dev
Ver el actual / borrar (debe estar vacío).

Usarlo en el código

locals {
  entorno = terraform.workspace   # "dev", "prod"…
}

resource "docker_container" "chanchito" {
  name = "chanchito-${terraform.workspace}"
  # ...
}
!

Es fácil aplicar en el workspace equivocado. Para dev/prod reales, mucha gente prefiere una carpeta por entorno (ver Módulos y proyecto).

8

Variables de entorno

Cambian el comportamiento de la CLI sin tocar el código.

Las más útiles

VariablePara quéEjemplo (PowerShell)
TF_VAR_<nombre>Valor de una variable de Terraform (ideal para secretos)$env:TF_VAR_mongo_password = "<password>"
TF_LOGLogs internos: TRACE, DEBUG, INFO, WARN, ERROR$env:TF_LOG = "DEBUG"
TF_LOG_PATHMandar esos logs a un archivo$env:TF_LOG_PATH = "tf.log"
TF_CLI_ARGS_planFlags extra para un comando$env:TF_CLI_ARGS_plan = "-parallelism=5"
TF_INPUT0 = no preguntar nada (CI)$env:TF_INPUT = "0"
TF_IN_AUTOMATIONSalida más corta pensada para CI$env:TF_IN_AUTOMATION = "1"
TF_DATA_DIROtra carpeta en vez de .terraform/$env:TF_DATA_DIR = ".tf-dev"
i

En Bash: export TF_VAR_mongo_password="<password>". Para borrarla en PowerShell: Remove-Item Env:TF_LOG.

9

CI, tests y extras

Lo que suele correr un pipeline.

Pipeline típico

# en cada pull request
terraform fmt -check -recursive
terraform init -input=false
terraform validate
terraform plan -input=false -out=tfplan

# al mergear a main
terraform apply -input=false tfplan
✓

fmt -check falla si algo no está formateado: buen primer filtro.

Otros comandos

terraform test
Corre los tests de *.tftest.hcl (planes o applies de prueba con asserts).
terraform login
Token para HCP Terraform / registry privado.
terraform metadata functions -json
Lista todas las funciones disponibles en tu versión.
terraform -chdir=infra/dev plan
Ejecutar en otra carpeta sin hacer cd.
